## 2. New paragraphs (Architecture)

- **Call recorder** (2026-11-06, `src/capture.ts`, `src/capturesend.ts`, `src/callapps.ts`, `src/webview/capture.ts`, `media/capture.html`): records all of the computer's sound and the microphone as one transcript. `CallCapture` (main side: `state`, `id`, `busy`, `seconds`, `start(title, app?)`, `stop()`, `allowCapture(session)`, `message`, `dispose`) owns a hidden-able 360x96 panel window (`media/capture.html`, bridge `Page 'capture'`; it may call only `/^\/recordings([/?]|$)/` and send only `captureState`, `captureDone`, `captureHide`, `captureOpenSettings`: `CAPTURE_ONLY` in `src/bridge.ts`). The page records (`getDisplayMedia` answered by `session.setDisplayMediaRequestHandler` in `allowCapture`, for that page only; Mac flags `MacLoopbackAudioForScreenShare,MacSckSystemAudioLoopbackOverride` in `main.ts`) and sends 16 kHz PCM in chunks through `TrackSender` (`capturesend.ts`), the tracks `mic` and `system`; chunks that never reached the engine are counted as `lost` and sent with `finish`. Should the page die, `CallCapture` finishes the recording from main (`finish` option). Main side: `startCall()`, `stopCall(): Promise<string|null>` (the transcript id) and `toggleCall()` in `main.ts`; the key is `meetingKey` (`KeyAction 'meeting'`, none by default, `keysOk.meeting`), also `TrayCommand 'call'`, `AppView.call {state, seconds}`, the app window's `toggleCall`; the panel's place is `callPanelOffset` (dragged), first use asks consent once (`callConsentSeen`), the Mac asks for the microphone and Screen Recording (`screenAllowed`, `captureOpenSettings` opens the system's settings). `callapps.ts`: `callApp(processNames)` finds one known call program (Zoom, Teams, Telegram, Discord, Slack, FaceTime, Skype, Webex; none or two -> null), `callTitle(app, at)` the default title, `runningProcessNames()`. `recordingNow()` (red tray dot) includes the call; quitting during a call asks (`quitDuringCall`) and saves within 30 s. Only ids and numbers are logged.
- **Engine side of calls**: `POST /recordings` takes `source: "system"` and track key `system`, and `app` (<= 80 chars, kept in `job` and in `transcript.json`); `POST /recordings/{id}/finish` takes `lost` (>= 0, in `transcript.json` only when > 0). `merge.meeting(mine, theirs, turns, track="tab")` treats `system` exactly as `tab` (the two-track path is `kind in ("meet","system")` with `mic` and `tab` or `system`; the mic is "Me", the system's voices are split by the model); `export.SOURCES["system"] = "Call"`; default title "Call". `engine/store.py` has the columns `summarized` and `app` (added by `alter table` when missing; `GET /transcripts` rows carry them, the fts index holds title + utterances + summary text); `redo` keeps `summary`, `app`, `lost`. Tests: `engine/tests/test_call.py`.
- **Summary** (2026-11-06, `src/summary.ts`, `src/summaryflow.ts`, the engine's `PUT /transcripts/{id}/summary`): a recorded transcript's summary made by the person's local model (`settings.model`, the same file and `LlamaServer` as Check; nothing is downloaded for it). `summary.ts`: `SummaryTemplate` = `general | standup | interview | lecture | own` (`SUMMARY_TEMPLATES` in `settings.ts`, the person's own instruction `callOwn` <= `SUMMARY_OWN_MAX`), `splitParts` (~1200 s or 12000 chars a part), `createSummarizer(...).summarize(input, options, onProgress, signal)` (a pass per part with a json schema `SummaryJson {short, decisions, tasks{who,what,due}, questions, topics{title,at}}`, then a joining pass), `renderSummary` (Markdown with `### ` sections, headings per en/uk/ru, topics as `- [mm:ss] title`), and **`checkSummary(json, input, translated)` which is code's, never the model's, decision**: a task's `due` and `who`, and any item with a number, survive only if the text carries them (4-letter stems; `translated` = `mine` in another language, checks numbers only), topics outside the recording's length are dropped. `summaryflow.ts` is pure and shared with the page (no node modules): `summaryInput(transcript)`, `secondsLeft`, `autoSummaryWanted(auto, modelReady)`, `TOPIC_STAMP`/`topicIn` (a topic's time becomes a link to the sound). `main.ts`: `makeSummary(id, {template, own, mine})` (one at a time per id, `summaries` map -> `AppView.summaries {part, parts, started, error?}`, aborted by `cancelSummary`, saved by `PUT`, a failure stays with its error until retried), `summaryWhenDone(id)` (after `stopCall()`: polls the transcript every 5 s, up to 6 h, and makes the summary by itself when `callSummaryAuto` and the model is here). Settings: `callSummaryAuto`, `callTemplate`, `callOwn`, `callSummaryMine` (written in the person's own language, `native`, else in the call's). page -> main (APP_ONLY): `summarize {id, template, own?, mine}`, `cancelSummary {id}`. `PUT` answers 404 unknown id, 409 while not `done`, 400 on an empty text or > 100 000 characters; `null` removes the summary; it lives in `transcript.json` `summary` and is exported on top (`## Summary`, then `## Transcript`; `notes.write_transcript` too). Summary text is never logged (reports carry logs).
- **Keyboard on a Mac** (2026-11-06; `build/kbd-mac.swift`, `src/kbdmac.ts`, `src/kbdmac-worker.ts`, built into `vendor/kbd-mac`, `dist/kbdmac-worker.js`): the Mac twin of `kbd-worker.ts`. `kbd-mac` is a CGEventTap that tells the worker each key and click as a JSON line on stdout and waits `ANSWER_MS` (120 ms) for whether to keep the key from the program; it types (`press`, marked `OWN`/`REPLAY`), switches the input source (`select`), says whether the focused field is a password (`field`), plays sounds; `kbd-mac layouts` prints the layouts. `kbdmac.ts`: `MAC_TO_VK`/`VK_TO_MAC` (Mac key code as a Windows virtual key, so `Typist` is unchanged), Cmd is Ctrl, Option is Alt, Control is Win (`hotkeyLabel` shows Control as the Command sign), `macKeyboardLayouts`. `keyboard.ts` picks the worker by platform (`macHelper`); the badge stands by the pointer (no caret place yet), no full-screen check (`ponytail:` comments mark both). **Accessibility**: without the permission the tap sees no key; the worker says `macAccess` once, main sets `keysUnseen` and `keyboardTrouble = 'macAccess'` (Keyboard page and Voice typing page warn, with a link to `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`); a key Electron can hold stays Electron's on a Mac (`registerShortcuts`, the menu key too) so it works without Accessibility. Snip/OCR on a Mac: `vendor/ocr-mac` (`build/ocr.swift`), `vendor/clip-mac` (`build/clip-mac.swift`), `snipMac`.
- **Hold to talk** (2026-11-06, `src/holdtalk.ts`, `settings.dictateHold`, off by default, Voice typing page): a dictation key (`dictate`, `english`, `practice`; never a note, never Ctrl+C twice) held `HOLD_TAP_MS` (300 ms) or more finishes its phrase on release; a shorter press is the old toggle. `HoldToTalk.pressed(at, starting)` / `released(at)`. The key goes to the keyboard thread whatever it is (`keyboard.ts apply`, `held`), because only the hook sees a key go up: `Typist` sends `hotkeyUp {action}` (`typist.ts holdKey`), `KeyboardEvents.hotkeyUp` -> `dictation.release()` in `main.ts`; `KeyboardEvents.hold()` tells the thread the setting. While `keysUnseen` (Mac without Accessibility) the setting is ignored and the key falls back to Electron's toggle (`main.ts` near line 2979).

## 3. `.autopilot/PROGRESS.md` (new subsection under Commands or a "Working here" heading)

- `.autopilot/` is the build pipeline's folder (`.autopilot/README.md` describes it; one folder per run, `<date>-<project>/`, `--wip` while running). `.autopilot/PROGRESS.md` is what is left after the last run: not done, known bugs, agreements. Any edit made without the autopilot first reads `PROGRESS.md` (so a known bug is not "found" again), and after the edit appends one line there (date, what changed, what is still open). The file may be absent before the first finished run: create it with a title and that line. Do not edit other files in `.autopilot/` by hand (`state.js`, `dashboard.html` are written by the pipeline).
