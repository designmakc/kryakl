# Спецификация: запись и итоги созвонов из любой программы

## Задача
«Я созваниваюсь в Zoom, Teams, Telegram, Meet или смотрю вебинар. Хочу одной клавишей записать и себя, и собеседников, а после — получить расшифровку по говорящим и короткий итог: о чём говорили, что решили, кто что делает. Всё на моём компьютере, без облака.»

## Решение
Новая кнопка «Записать созвон» (клавиша, пункт трея, кнопка на странице «Записи и встречи»). Крякл пишет весь звук компьютера и микрофон в маленькой панели с таймером, паузой и стопом. После стопа запись встаёт в существующую очередь расшифровки; «Я» — из микрофона, собеседники разделены по голосам. Затем локальная модель (Gemma) делает итог по шаблону; его можно поправить, пересоздать, скопировать, он идёт в экспорт и в базу знаний. Работает на macOS и Windows одним кодом (Windows не проверена на этом Mac).

## Решения по реализации
- **Захват в скрытом окне-панели** `media/capture.html` (+ `src/webview/capture.ts`): одно окно и пишет, и показывает панель; «Скрыть» прячет окно, запись идёт (как свёрнутая панель диктовки). Почему: меньше окон и сообщений между ними.
- **Звук компьютера**: главный процесс ставит `session.setDisplayMediaRequestHandler` только для этого окна (по `webContents` запроса; остальным отказ), отдаёт первый экран из `desktopCapturer.getSources({types:['screen']})` и `audio: 'loopback'`. Страница вызывает `getDisplayMedia({video:true, audio:true})`, останавливает видео-дорожки.
- **Mac-разрешение**: `systemPreferences.getMediaAccessStatus('screen')`; не `granted` → `dialog.showMessageBox` с объяснением, «Открыть настройки» → `shell.openExternal('x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture')`. Микрофон — `askForMediaAccess('microphone')`. В `electron-builder.yml` — описания для экрана/звука и микрофона «и созвоны».
- **Отправка кусков** через `host-call` (`/recordings…`), как диктовка; `bridge.ts` получает страницу `capture` с правом только на `/recordings`. Повторы и `lost` — как в `offscreen.js` (5 попыток, 409 = готово).
- **Движок**: `source "system"` и дорожка `"system"` — новые значения; двухдорожечная ветка срабатывает для `kind in ("meet","system")` при `mic` + (`tab` или `system`); `system` везде, где сейчас `tab` (merge.stored/resplit). `finish` принимает `lost`, расшифровка хранит `lost` и `app`.
- **Итог хранится в `transcript.json`** ключом `summary = {text, template, mine, language, made, edited?}`; `text` — Markdown с разделами, темы — строки с `[мм:сс]`, по ним страница делает ссылки. Новый маршрут `PUT /transcripts/{id}/summary` (тело `{summary}` или `{summary:null}`), `redo` сохраняет `summary`, `store` переиндексирует текст итога для поиска и отдаёт в списке `summarized` (новая колонка с миграцией). Почему: удаляется вместе с папкой, отдаётся существующим `GET`.
- **Итоги делает главный процесс** (`src/summary.ts`, чистая логика + фабрика как `checker.ts`): части по времени реплик (~20 мин, ≤12 000 знаков), map — `json_schema` частичного итога, reduce — общий; при одной части сразу общий. Рендер JSON → Markdown в коде; заголовки разделов на языке итога (en/uk/ru, прочие — английские). Проверка выдумок — в коде (история 38). Модель — `settings.model`, `temperature 0`, `enable_thinking:false`.
- **Состояние итогов** в `AppView.summaries` (по id: часть/всего/начало/ошибка); сообщения страницы `summarize {id, template, own?, mine}`, `cancelSummary {id}`. Автоитог: главный процесс после `finish` своей записи опрашивает `GET /transcripts/{id}` раз в 5 с до `done`, затем делает итог, если `callSummaryAuto` и модель `ready`.
- **Настройки**: `meetingKey` (''), `callSummaryAuto` (true), `callTemplate` ('general'), `callOwn` (''), `callSummaryMine` (false), `callConsentSeen` (false), `callPanel` позиция — общая с `dictationBadge` не берём: своя `callPanelOffset`.
- **Выход/сон**: `before-quit` при записи — `preventDefault`, вопрос, затем остановка и повторный `app.quit()`; `powerMonitor.on('suspend')` — остановка и сохранение.
