## Что должно заработать

Движок речи принимает запись созвона: источник `system`, дорожки `mic` + `system` сводятся как у Google Meet («Я» из микрофона, собеседники по голосам, эхо из динамиков убирается), имя программы и число потерянных кусков сохраняются. У расшифровки появляется итог: его можно записать, стереть, он ищется, идёт в экспорт Markdown/TXT/DOCX и в базу знаний сверху, переживает «расшифровать заново». В `src/summary.ts` — ядро итогов: деление длинной встречи на части, промпты по шаблонам, map-reduce через локальную модель, проверка выдумок, сборка Markdown.

## Из брифа, дословно

> «`source: 'system'` и имя программы в `POST /recordings`; дорожка `system` наравне с `tab` в `merge.meeting`»
> «Без наушников микрофон слышит динамики; дубли убирает сведение дорожек»
> «Коротко — 3–5 предложений; Решения; Задачи — кто, что, срок (если прозвучал); Открытые вопросы; Главные темы с отметкой времени»
> «Шаблоны: «Общий», «Планёрка», «Интервью», «Лекция/вебинар» + свой текст-инструкция»
> «Длинные встречи — частями (map-reduce: итог каждого куска ~20 мин, затем общий), чтобы влезать в контекст модели»
> «модели запрещено придумывать имена, сроки и цифры, которых не было; задача без срока — без срока»
> «Экспорт: Markdown (итог + расшифровка), DOCX (уже есть `export.py`), TXT; «В базу знаний» — существующий `/transcripts/{id}/to-kb`, итог сверху»
> «Удаление записи удаляет звук, текст и итог»

## Критерии приёмки

- [ ] `POST /recordings` с `source:"system"`, дорожками `mic`+`system` и `app` создаёт запись; заголовок по умолчанию «Call»; `finish` с `lost:2` даёт `lost: 2` и `app` в transcript.json (тест движка)
- [ ] Двухдорожечная запись `mic`+`system` идёт по ветке `merge.meeting`: слова микрофона — «Me», повтор из `system` в ±1,5 с выброшен (тест)
- [ ] `PUT /transcripts/{id}/summary` сохраняет/стирает итог; 409 пока не `done`, 404, 400 по контракту; `GET /transcripts` отдаёт `summarized`, поиск находит слово из итога; `redo` сохраняет `summary`, `app`, `lost` (тесты; миграция колонки на существующей базе)
- [ ] Экспорт md/txt/docx и `to-kb` — итог сверху под заголовком «Summary», без итога — как раньше (тесты)
- [ ] `splitParts` режет по ~1200 с и ≤12 000 знаков, не разрывая реплику; `renderSummary` даёт разделы с заголовками на языке (en/uk/ru, иначе en), пустой раздел «—», темы «- [mm:ss] …», строку о потерянных кусках при `lost>0`
- [ ] `checkSummary` убирает выдуманный срок, чужое имя в «кто», пункт с числом, которого нет в тексте, тему за пределами записи (тесты на каждый случай)
- [ ] `createSummarizer.summarize` на одной части делает один запрос, на трёх — три map и один reduce, сообщает прогресс, уважает `AbortSignal`, промпт оборачивает свою инструкцию правилами и просит язык встречи или родной (`mine`) — тест с подменённым `fetch`
- [ ] `npm run typecheck`, `npm test`, `npm run test:engine` зелёные
